# 重新設計中性色

Blocked by: none

## Why

日間的暖白底太黃、太灰，暗黑的炭黑底太綠、太亮；文字與邊框也帶綠調。使用者要把兩個風格套系共用的中性色換成一致的冷藍灰，表面層級、文字與邊框的色相要對得上，且不降低現有的可讀性。

## Scope

- 中性色 8 個角色在日間與暗黑的新值，兩個風格套系共用（`packages/tokens/src/mode/`）。
- 由中性色推算或依賴中性色的輸出跟著更新：CSS 與程式資料、設計變數規格文件、元件庫設計檔的設計變數、強調色推算出的焦點框與滑過、按下色。
- PR-STYLE-27、PR-STYLE-29 的文字改為容許這次刻意的改值，快照測試只對中性色放行。
- 樣張首屏底色、截圖基準、README 截圖、前端規格的色表、0.2.0 升級說明。

## Promises

PR-STYLE-27 — `@luca-style/tokens` 的 css、data、typography 三種輸出：既有變數的名稱、結構和值都與 0.1.0 相同；例外是中性色 8 個角色的值，改為 PR-STYLE-48 所列，其餘任何變數的值與 0.1.0 不同時快照測試失敗。（改寫，編號不變）
PR-STYLE-29 — 專案沒有覆寫時，資訊密度與元件外形沿用所選風格套系的預設值，密度與外形與 0.1.0 相同；中性色依 PR-STYLE-48。（改寫，編號不變）
PR-STYLE-48 — 中性色在日間／暗黑的值為：`bg` #F7F8FA／#111317、`surface` #FFFFFF／#1A1D22、`surface-subtle` #F1F3F5／#23272D、`text` #2C2E31／#EFF1F5、`muted` #696B6F／#AEB0B4、`border` #E0E2E6／#3C3E41、`control-border` #85878B／#6F7175、`accent-ink` #FFFFFF／#111317。
PR-STYLE-49 — 中性色 8 個角色在精緻活力與精緻專業的值相同，只隨明暗模式變化。
PR-STYLE-50 — 兩個套系、日間與暗黑：`text`、`muted` 對 `bg`、`surface`、`surface-subtle` 的對比都至少 4.5:1；`control-border` 對這三層都至少 3:1。
PR-STYLE-51 — 樣張在 React 掛載前的首次繪製，頁面底色就是該明暗模式的 `bg`。
PR-STYLE-52 — `docs/images/` 的四張 README 截圖（套系 × 明暗）頁面底色等於該組合的 `bg`。
PR-STYLE-53 — `docs/consumer-guide.md` 的 0.2.0 升級說明列出中性色 8 個角色的舊值與新值，並說明使用端寫死舊色碼處要改成設計變數。
PR-STYLE-54 — `docs/05_frontend_spec.md` 的色表與 PR-STYLE-48 一致，三層使用「頁面底色、卡片表面、次要表面」的名稱。

既有承諾照常適用並以新值驗收：PR-STYLE-28（規格文件）、PR-STYLE-33 與 PR-STYLE-46（推算角色與焦點框對比）、PR-STYLE-41（axe）、PR-STYLE-42（截圖基準）、PR-FILE-16（元件庫設計檔的值與程式一致）。

## Out of scope

- 各風格套系自己的顏色：強調色、柔和底色、點綴色、語意狀態色。它們依套系帶色相，是刻意的差異。
- 使用端覆寫中性色。開放覆寫要另定對比補正規則。
- 版本號。0.2.0 尚未發布，改動併入 0.2.0。
- 使用端專案（automated_trading、badminton）的升級，各自另開議題。
- `docs/delivery-verification.md` 中舊色碼的驗收紀錄；那是當時的證據，不改寫。
- 資訊密度與元件外形。

## Decisions

- 中性色採冷藍灰（OKLCH 色相約 260），文字與邊框彩度 0.006、明度沿用舊值；不採用保留綠調、完全中性灰、彩度 0.012 或 0.020。見 decision-log 2026-10-29。
- 範圍是中性色全部 8 個角色；不採用只改 `bg`（表面與文字的色相對不上）或只改表面層級。
- 兩個套系共用一組中性色；不採用依套系各一組。
- 暗黑 `accent-ink` 改為與新底色同值 #111317；不採用維持 #151A18，也不採用參照 `{bg}`（會把兩個用途不同的角色綁在一起）。
- PR-STYLE-27 加入中性色例外；不採用把快照基準整個換成新值，也不採用只寫升級說明不比對值。見 decision-log 2026-10-29。
- 改動併入未發布的 0.2.0；不採用另發 0.3.0。
- 不開 ADR：改的是可回頭的色碼與可收回的承諾範圍。

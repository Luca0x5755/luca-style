# 長時間編輯的壓力測試

Blocked by: ISSUE-019

## Done when

- 單一連續 MCP 工作階段至少 500 次寫入呼叫，加上至少 1 小時的手動編輯，全程不當機（PR-FILE-21）。
- 至少 6 個瀏覽器分頁記憶體取樣點（起點、每 100 次寫入、終點）記在 `docs/delivery-verification.md`（PR-FILE-22）。

## Context

這是針對「記憶體累積後當機」本身的測試，是試點裡最重要的一條。背景見 ISSUE-017 與 ADR 0008。

## Blocked by

ISSUE-019

## Notes

- 1 小時手動編輯需要使用者本人操作，代理做不了；票完成時要使用者確認。
- 500 次寫入可用腳本反覆改某個母版的屬性再復原。
- 記憶體是否趨於平穩由使用者判定，不要自己訂數值。

# 其他專案套用 Luca Style 的提示詞

在目標專案開啟代理工作階段，複製下方整段提示詞。先執行 `git clone https://github.com/Luca0x5755/luca-style.git` 取得設計來源，再填寫輸入欄位；`<設計來源路徑>` 請替換為實際 clone 的本機路徑。

套系建議：活動、社群等親和型產品選 `vibrant`；金融、資料監控等高密度產品選 `professional`。新專案依產品定位選一套，同專案維持一致。

## 可直接複製的提示詞

```text
請將此專案的前端套用 Luca Style 設計系統，完成實作與瀏覽器驗證。

【輸入】
- 設計來源：<設計來源路徑>
- 風格套系：依本專案定位選擇（vibrant／精緻活力・潮汐；professional／精緻專業・石墨紫）
- 套用範圍：現有前端的共用外殼、共用元件與主要業務頁面
- 專案強調色：沿用套系預設；已有明確品牌要求時提供日間主色，暗黑主色選填
- 優先頁面：依主要使用流程決定

【先讀取與盤點】
1. 讀取目標專案的 AGENTS.md、工程規範、前端入口與建置設定，確認框架、React 版本、路由、現有元件庫及樣式方案。
2. 從設計來源讀取：
   - docs/consumer-guide.md：封裝、公開 API、主題與資產接入方式。
   - docs/05_frontend_spec.md：色彩、響應式字級、間距、外形與載入動畫的正式規範。
   - docs/03_architecture_design.md：設計系統的責任與覆寫邊界。
   - examples/consumer/src/main.tsx：公開介面的最小使用範例。
   - packages/tokens/src/（DTCG 分層檔）：最新變數來源；數值以此與正式規範核對。
3. 需要核對視覺設計時，使用 OpenPencil 工具開啟元件庫設計檔 docs/mockup/luca-style-library.fig（只含設計變數與 23 個母版，沒有頁面 frame；頁面範本以樣張網站為準），以 Suite、Mode、Suite x Mode 三個集合的模式切換套系與明暗。透過工具讀取 .fig，工具不可用時明確記錄尚未完成 mockup 比對。專案自己畫設計稿時，複製此檔並匯入專案強調色：依 docs/consumer-guide.md〈複製元件庫設計檔並匯入專案強調色〉執行 scripts/design/import-accent.js；luca-style 更新後的重新匯入也寫在該節。
4. 列出主要路由、共用元件與載入／空白／錯誤狀態的套用清單，說明採用的套系與接入方式，再持續執行。已有明確答案的事項直接依規範處理；僅在真正阻塞的產品或技術決策上詢問。

【實作】
5. 保留目標專案的業務流程、資料合約、權限、路由與既有可用功能；以設計系統更新呈現和互動。業務頁面使用本專案的實際資料與文案。
6. 依技術棧接入：
   - 相容的 React 專案：依 consumer-guide 建置並封裝設計來源的 tokens 與 React 套件，安裝實際產出的同版 tarball。先確認 React peer dependency 相容；有版本衝突時先提出可行處理方式。使用公開 exports，避免直接引用來源 repo 的 packages/*/src。
   - 其他框架：接入公開 tokens，依相同規範建立目標框架的元件；先盤點現有元件可沿用的行為與無障礙功能。字體、OFL 授權及載入動畫資產依目標專案的資產管線交付，記錄來源版本與同步方式。
   - 若無法讀取設計來源，先回報缺少的路徑或檔案，取得內容後再實作精確色票與規格。
7. React 入口載入 tokens/css、react/fonts.css、react/css，以 ThemeProvider 設定選定套系。模式控制在 Provider 內透過 useTheme 實作；API 與完整接入細節依 consumer-guide。
8. 首次明暗模式跟隨系統，支援日間、暗黑、跟隨系統與偏好保存。HTML／SSR 首屏在應用程式與外部 CSS 載入前即設定正確背景及 color-scheme，並同步後續切換；直接開頁、重整及跨頁載入都要檢查白底閃爍。使用 `ThemeProvider target="document"` 讓主題套在整頁，並把 `themeInitScript({suite})` 的回傳字串放進 `<head>` 行內腳本防止首屏閃爍（參考設計來源 apps/showcase/vite.config.ts）；SSR／CSP 需由目標專案自行配合。
9. 以語意 tokens 和字級角色建立版面，依前端規範處理電腦、平板、手機。精緻活力使用較寬鬆密度與圓潤外形；精緻專業使用較密集節奏與俐落外形。套用既定角色，讓小螢幕以堆疊、換行或可操作的表格捲動適應內容。
10. 成功、警告、錯誤使用所選套系的正式狀態色並搭配文字或圖示。活力採「海岸訊號」，專業採「冷杉與琥珀」；同套系跨專案維持一致。業務資料的漲跌、正負、紅綠另定 data tokens 與圖例，與操作結果分開。
11. 內容區塊載入時使用所選套系的正式 GIF：活力「潮汐波紋」、專業「方序循環」。React 使用 ContentState state="loading"；其他框架沿用套件 loading/ 內正式資產。依明暗模式取圖，減少動態時換成對應靜態 PNG，保留載入文字與 aria-busy；載入結束移除動畫。GIF 循環不代表實際進度。空白與錯誤狀態使用相應文案與重試操作。
12. 自訂專案強調色時以 `AccentInput` 提供日間主色（暗黑主色、點綴色、柔和底色選填，沒給由系統推算；滑過、按下、焦點框一律推算）。有給的顏色不經對比修正，自行檢查文字、按鈕、卡片與柔和底色的對比，保持狀態色語意及數值獨立。字體與授權一起部署。

【驗收與交付】
13. 執行目標專案既有的 build、typecheck、lint 及受影響流程的測試；依其實際工具選擇命令。
14. 使用 Playwright 檢查所選套系的日間／暗黑、390／834／1280px、正常／載入／空白／錯誤狀態。驗證模式保存、系統模式變動、切頁首屏、鍵盤與焦點、表單驗證、表格可讀性、內容無水平溢出，以及 GIF／靜態替換的圖檔可取得。對有角色的可捲動表格，驗證區域內可捲動且頁面本身不溢出。
15. 一般文字與背景對比至少 4.5:1；大字至少 3:1，必要控制邊界至少 3:1。使用實際 computed styles 檢查，涵蓋專案強調色覆寫與各種表面。
16. 對照 mockup 檢查字體、字級、外形、間距、色彩及狀態呈現，保留代表頁面的截圖和差異說明。分別說明行為驗證與視覺比對的完成範圍；只有實際執行過影像差異比對，才聲稱完成像素比對。
17. 在目標專案文件記錄套系、設計來源 commit、套件版本／安裝方式、資產交付方式、允許的局部覆寫、已完成頁面及驗收結果，供後續頁面沿用。

交付時摘要列出：已修改頁面與元件、預覽方式、測試結果及具體未完成項目。完成已授權的實作；git 提交與部署依本專案既有授權及流程處理。
```

## 已套用舊版的專案：升級提示詞

適用於已依舊版（設計稿為單一 `docs/mockup/components.pen`）套用過 Luca Style 的專案。設計來源這次的差異是設計稿正本：改為兩個依套系拆開的 OpenPencil `.fig`，`components.pen` 已移除；tokens 與 React 套件的公開 API、版本號（0.1.0）都沒有變，所以升級以文件、設計稿比對與資產核對為主，不需要重寫元件。若專案連 tokens 數值也沒更新，才依步驟 4 處理。

先在設計來源 `git pull`（或重新 clone）取得最新內容，再複製下方提示詞。

```text
請將此專案已套用的 Luca Style 升級到最新設計來源，只處理差異，不重做已完成的套用。

【輸入】
- 設計來源：<設計來源路徑>（已更新到最新）
- 風格套系：沿用本專案已選的套系（vibrant 或 professional），不更換
- 套用範圍：沿用先前的範圍；本次不新增頁面

【先確認舊狀態】
1. 讀取本專案記錄 Luca Style 套用狀態的文件，找出：採用的套系、當時的設計來源 commit、套件安裝方式（tarball、複製 tokens，或在其他框架自建元件）、局部覆寫與已完成頁面。找不到記錄時，從 package.json、入口檔與樣式推斷，並在最後補寫記錄。
2. 在設計來源執行 `git log --oneline <舊 commit>..HEAD -- packages apps docs/05_frontend_spec.md docs/03_architecture_design.md`，列出舊 commit 之後與本專案有關的變更。舊 commit 不明時，改以下列差異清單核對。

【已知差異與處理】
3. 設計稿來源：原本比對的 `docs/mockup/components.pen` 已移除（git 歷史找得回）。改開元件庫設計檔 docs/mockup/luca-style-library.fig，透過 OpenPencil 工具讀取。它只含設計變數與 23 個母版，沒有頁面 frame；頁面的版面、狀態與命名以樣張網站為準。工具不可用時，明確記錄尚未重新做 mockup 比對。
4. tokens 與套件：比對設計來源 `packages/tokens/src/` 的 DTCG 分層檔與專案目前使用的數值。公開 API 與 0.1.0 版本沒有變，若數值一致就不重新安裝；不一致才依 docs/consumer-guide.md 重新建置、封裝並安裝同版 tarball（兩個套件版本須一致），或同步其他框架的自建 tokens。
5. 文件連結：專案文件中凡是指向 `components.pen`、「唯一設計檔」或「左右兩側並排」的敘述，改為元件庫設計檔 `docs/mockup/luca-style-library.fig` 的路徑。
6. 若專案在第 1 步記錄的 commit 之前就有自訂覆寫（強調色、密度、資料色），確認它們沒有被新的套系預設取代；覆寫值不變。

【驗收】
7. 執行專案既有的 build、typecheck、lint 與測試；有升級套件或 tokens 時，再用 Playwright 檢查所選套系的日間／暗黑、390／834／1280px、正常／載入／空白／錯誤狀態，並確認字體、授權與載入動畫資產仍可取得。沒有改動程式碼時，說明只做了文件與記錄更新，不聲稱重做了視覺驗收。
8. 若有執行 mockup 比對，保留代表頁面的截圖與差異說明；只有實際跑過影像差異比對才聲稱像素比對。
9. 更新專案記錄：新的設計來源 commit、所用設計檔名稱、套件版本與安裝方式、已核對的差異與結果。

交付時摘要列出：變更檔案、與舊版相比實際不同的項目、測試結果、具體未完成項目。git 提交與部署依本專案既有授權及流程處理。
```

## 指定套系時的輸入範例

只需替換提示詞中的輸入區，後續步驟共用。

### 精緻活力（vibrant）

```text
【輸入】
- 設計來源：<設計來源路徑>
- 風格套系：vibrant／精緻活力・V2 潮汐
- 套用範圍：現有前端的共用外殼、共用元件與主要業務頁面
- 專案強調色：沿用套系預設
- 優先頁面：先盤點既有主要流程，再依使用頻率安排
```

### 精緻專業（professional）

```text
【輸入】
- 設計來源：<設計來源路徑>
- 風格套系：professional／精緻專業・P3 石墨紫
- 套用範圍：現有前端的共用外殼、共用元件與主要業務頁面
- 專案強調色：沿用套系預設
- 優先頁面：先處理主要總覽，再處理資料表格與設定頁；業務漲跌色維持獨立
```

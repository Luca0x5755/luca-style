在這個專案做一個 SaaS 產品的「行銷與定價」單頁。開始前先讀專案根目錄的 `README.md`。

## 功能

- 頁首與主視覺：產品名稱、一句價值主張、主要行動按鈕（開始試用）和次要行動按鈕（聯絡業務）。
- 功能亮點：至少 3 個區塊，各有標題與一兩句說明。
- 定價方案：方案資料從一個假的非同步函式取得（用 `Promise` 加延遲模擬 API，不接後端），至少 3 個方案（例如入門、專業、企業），各有名稱、價格、功能清單和行動按鈕，其中一個標示為推薦。可以切換「月繳」和「年繳」，年繳比月繳固定便宜 20%（年繳的每月價格 = 月繳價格 × 0.8）。
- 方案比較表：列出各方案的功能差異。
- 常見問題：至少 4 題，可以展開收合。
- 頁尾：聯絡方式與版權文字。

## 四種狀態

網址參數 `state` 決定「定價方案」區（方案卡與比較表）的狀態，其餘區塊不受影響。沒有參數時為 `success`：

- `/?state=loading`：方案資料載入中，一直維持載入中，不要自動切到其他狀態。
- `/?state=empty`：目前沒有開放購買的方案。要說明原因，並提供聯絡業務的操作，不是顯示空白。
- `/?state=error`：假的 API 呼叫失敗，要說明失敗並有重試的操作。重試後依網址參數的狀態重新取得資料，所以仍會失敗也沒關係，但要再次顯示錯誤。
- `/?state=success`：顯示假資料。

空狀態與錯誤狀態的文字和操作要明顯不同。每種狀態在畫面上可見的容器要加 `data-eval-state="<狀態>"`，例如 `<section data-eval-state="empty">`。同一時間畫面上只能有一個 `data-eval-state` 容器，且要同時包住方案卡與比較表。

## 要求

- 寬度 1280、834、390 都要能用，畫面不能左右捲動。
- 符合無障礙要求，例如表單欄位要有標籤、文字對比要足夠。
- `npm run build` 要成功，輸出在 `dist/`，頁面從根路徑 `/` 開啟。
- 只能使用 `npm install <套件>`、`npm run build`、`npx tsc` 這三種指令；不要啟動開發伺服器。
- 完成並建置成功後結束，用幾句話說明做了什麼。

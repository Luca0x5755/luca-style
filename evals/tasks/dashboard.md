在這個專案做一個「服務監控」儀表板頁面。開始前先讀專案根目錄的 `README.md`。

## 功能

- 摘要列：四個指標卡，顯示請求量、錯誤率、平均回應時間、線上服務數，每張卡有目前數值和相較上一段時間的變化（上升或下降）。
- 趨勢圖：顯示最近 24 小時的請求量與錯誤率走勢。可以切換時間範圍（1 小時、24 小時、7 天），三個範圍都要有資料。圖要有文字替代，例如旁邊附一張同樣資料的表格，或可展開的資料表。
- 服務清單：表格顯示服務名稱、狀態（正常、降級、中斷）、回應時間、最近一次檢查時間。可以依狀態篩選，並按服務名稱排序。
- 告警：列出目前的告警（嚴重程度、服務、說明、發生時間），每筆可以標記為已確認。已確認的告警移到「已確認」區。
- 資料從一個假的非同步函式取得（用 `Promise` 加延遲模擬 API，不接後端）。假資料至少 8 個服務、5 筆告警，24 小時至少每小時一個資料點。

## 四種狀態

網址參數 `state` 決定整個儀表板資料區的狀態，沒有參數時為 `success`：

- `/?state=loading`：資料載入中，一直維持載入中，不要自動切到其他狀態。
- `/?state=empty`：帳號下還沒有任何受監控的服務（沒有服務也沒有資料）。要引導使用者新增第一個服務，不是顯示一堆零。
- `/?state=error`：假的 API 呼叫失敗，要說明失敗並有重試的操作。重試後依網址參數的狀態重新取得資料，所以仍會失敗也沒關係，但要再次顯示錯誤。
- `/?state=success`：顯示假資料。

空狀態與錯誤狀態的文字和操作要明顯不同。每種狀態在畫面上可見的容器要加 `data-eval-state="<狀態>"`，例如 `<section data-eval-state="empty">`。同一時間畫面上只能有一個 `data-eval-state` 容器，且要包住整個狀態區（摘要列、趨勢圖、服務清單、告警都在裡面）。

## 要求

- 寬度 1280、834、390 都要能用，畫面不能左右捲動。
- 符合無障礙要求，例如表單欄位要有標籤、文字對比要足夠。
- `npm run build` 要成功，輸出在 `dist/`，頁面從根路徑 `/` 開啟。
- 只能使用 `npm install <套件>`、`npm run build`、`npx tsc` 這三種指令；不要啟動開發伺服器。
- 完成並建置成功後結束，用幾句話說明做了什麼。
